## 核心发现

在汇报方面，除了制作复杂度外，HTML 几乎完胜 PPT。

但在 AI 时代，制作复杂度这一缺点几乎可以忽略。

## 提示词（持续更新）

配置推荐：

- 使用 Coding Agent（Claude Code、Codex……）
- 模型需要有强大的代码能力以及审美（推荐：Claude）

将论文原文附件（有 Latex 源码更好，至少要有 PDF）存放于工作目录中，并输出下述提示词：

```
我需要汇报 <论文名> 这篇论文，请你帮我制作用于汇报的 HTML。

注意：既然采用 HTML 去汇报（而非传统的 PPT），就要展示 PPT 无法做到但是却有利于演讲或者听者理解的元素，比如引入交互式、视觉、动态上的元素等等（注意，我仅列举了部分，你当然还可以尽情地发挥 HTML 的优势）。

制作过程中需要注意：
* 上面提到的 HTML 元素（包括你自己添加的元素），要合理使用，适配才是王道。
* 采用 Anthropic(https://www.anthropic.com/) 风格的主题
* 每页中的内容字体不能太小
* 页面中的内容中不要出现和提示词相关的解释或者描述（比如我用提示词让你将字体放大一点，你就不要在页面的内容中写“字体放大可读”这样的内容）
* 内容是内容，回答是回答，你不要将回答（比如功能的解释）放到内容中。换言之，我让你制作的内容中，不能看到你制作过程中留下的与内容无关的痕迹。

我的汇报时间大致是 <时间>，而且我的听众可能并不是专业人士，我要尝试让他们都听懂。
```
