## 多态

多态的定义：同一个调用，作用在不同对象上，表现不同。

```java
interface Animal { void speak(); }

class Dog implements Animal {
    public void speak() { System.out.println("汪"); }
}
class Cat implements Animal {
    public void speak() { System.out.println("喵"); }
}

public class Demo {
    public static void talk(Animal a) {
        a.speak();
    }
    public static void main(String[] args) throws Exception {
		// 多态的体现位置：同一个调用 talk(), 但作用的对象分别是 Dog 和 Cat，所表现的行为也不同
        talk(new Dog());
        talk(new Cat());
    }
}
```

输出：

```
汪
喵
```

针对 `talk` 的参数，编译器只会检查 `Animal` 有没有 `speak()` 方法。到底执行 Dog 的还是 Cat 的，要等**运行时**看传进来的是什么对象来决定。

>[!note]
> 从面向对象的视角看，这是“多态”的体现；从编译器和虚拟机的视角看，这是“动态分派（Dynamic Dispatch）”的体现

Java 中的任意一个类，都会继承 `Object` 类。你可以在 IDEA 中选中任意一个类，然后按 `Ctrl + H`，就能看到层级关系：

![[Pasted image 20261031221811.png]]

因此，`Object` 中的方法如果同时满足：

- 不是 `private`
- 不是 `final`
- 不是 `static`

则这些方法可以被任何任何类重写。

满足条件的方法：

- `hashCode()`
- `equals()`
- `toString()`

结合上面讲的“多态”，可以得到一个**结论**：调用 `Object` 的 `hashCode()`，实际跑的可能是任何一个类重写的 `hashCode()`。

## 集合会“自动”调用你对象的方法

HashMap 是 Java 集合框架（`java.util` 包）中最常用的数据结构之一：

```java
Map<String, Integer> scores = new HashMap<>();
// 存入键值对到哈希表
scores.put("Alice", 95);
```

`map.put(k, v)` 看起来只是存东西，其实 HashMap 内部会主动调用 `k` 的一些方法。

举个例子：

```java
class Key {
    int id;
    Key(int id) { this.id = id; }

    @Override public int hashCode() {
        System.out.println("hashCode 被调用, id=" + id);
        return id % 2;
    }
    @Override public boolean equals(Object o) {
        System.out.println("equals 被调用, id=" + id);
        return o instanceof Key k && k.id == id;
    }
}

Map<Key, String> m = new HashMap<>();
m.put(new Key(1), "a");
m.put(new Key(3), "b");
```

输出：

```
hashCode 被调用, id=1
hashCode 被调用, id=3
equals 被调用, id=3
```

原因：

- 每次 `put`，HashMap 都会先调 `k` 的 `hashCode()` 方法来算出该放进哪个桶
- 由于 `hashCode()` 被重写，`1 % 2` 和 `3 % 2` 都等于 1，两个 key 进了同一个桶，HashMap 必须调 `equals()` 判断它们是不是同一个 key

>[!tip]
> 这里其实还用到了[[#多态]]，HashMap 的源码虽然是固定的，但它内部调用的 `hashCode()`、`equals()` 跑的却是**放进去的那个对象自己的实现**。

## 反射

反射的定义：Java 程序在**运行时**可以查看并操作类的结构（比如有哪些字段、方法、构造器）。

换言之，有了反射，在**编写**、**编译**的阶段，甚至可以不用定义类，就能写好处理该类的一系列逻辑。但是在**运行的时候**，JVM 就必须要找到对应类的定义。

普通写法要求编译时就确定用哪个类、类的哪个方法：

```java
class User{
    public String name;
    public void setName(String name){
        this.name = name;
        System.out.println("你的名字是：" + this.name);
    }
}

public class Demo {
    public static void main(String[] args) throws Exception {
        User u = new User();
        u.setName("Tom");
    }
}
```

用反射时，类名和方法名可以是运行时才拿到的字符串：

```java
Class<?> clazz = Class.forName("com.example.User");
Object u = clazz.getDeclaredConstructor().newInstance();
Method m = clazz.getMethod("setName", String.class);
m.invoke(u, "Tom"); 
```

不难发现，编写代码时，你可以**先**不定义对应的类以及里面的属性、方法，只需要写好处理该类的对应逻辑。**但是**在最终运行时，无论是调用库，还是你自己写，都需要让 JVM 能找到 `User` 类的定义。

反射的价值主要体现在框架里，因为在写框架的时候，根本不知道将来使用框架的程序员会写什么类。但是在反序列化漏洞中，该机制通常用于：

- 突破访问修饰符的限制，拿到类、属性、方法等

## 动态代理

动态代理的定义：在**运行时**自动生成一个“替身”对象（动态代理对象），所有对它的方法的调用都会被拦下来，交给你写的一段统一的逻辑（处理器）来处理。

假设有一个 `UserService` 接口，他实现的核心逻辑就是“保存用户”：

```java
public interface UserService {
    void saveUser(String name);
}

public class UserServiceImpl implements UserService {
    @Override
    public void saveUser(String name) {
        System.out.println("保存用户: " + name);
    }
}
```

如果你想给核心逻辑添加日志信息，最直接的方式就是实现一个代理类（类似 Python 中的装饰器的用法）：

```java
// 静态代理类
public class UserServiceProxy implements UserService {
    private final UserService target;

    public UserServiceProxy(UserService target) {
        this.target = target;
    }

    @Override
    public void saveUser(String name) {
        System.out.println("[日志] 开始执行...");
        target.saveUser(name);
        System.out.println("[日志] 执行结束...");
    }
}
```

这被称为**静态代理**。因为一旦接口切换，你就得重新写一遍一样的代理类逻辑。

JDK **动态代理**则不同：

```java
import java.lang.reflect.InvocationHandler;
import java.lang.reflect.Method;
import java.lang.reflect.Proxy;

// 定义接口
interface UserService {
    void saveUser(String username);
}

// 目标类（实现接口）
class UserServiceImpl implements UserService {
    @Override
    public void saveUser(String username) {
        System.out.println("核心业务：保存用户 -> " + username);
    }
}

// 实现调用处理器（定义增强逻辑）
class LogInvocationHandler implements InvocationHandler {
    private final Object target; // 持有真实目标对象的引用

    public LogInvocationHandler(Object target) {
        this.target = target;
    }

    @Override
    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
        System.out.println("[前置日志] 准备执行方法: " + method.getName());
        
        // 通过反射调用真实目标对象的方法
        Object result = method.invoke(target, args);
        
        System.out.println("[后置日志] 方法执行完毕: " + method.getName());
        return result;
    }
}

// 测试生成代理对象
public class JdkProxyDemo {
    public static void main(String[] args) {
        UserService target = new UserServiceImpl();
        
        // 动态生成代理对象
        UserService proxy = (UserService) Proxy.newProxyInstance(
                target.getClass().getClassLoader(), // 类加载器
                target.getClass().getInterfaces(),  // 目标类实现的接口数组
                new LogInvocationHandler(target)    // 拦截处理器
        );
        
        // 调用代理对象的方法（实际上会触发 invoke 方法）
        proxy.saveUser("Alice");
    }
}
```

输出：

```
[前置日志] 准备执行方法: saveUser
核心业务：保存用户 -> Alice
[后置日志] 方法执行完毕: saveUser
```

其中的：

```java
UserService proxy = (UserService) Proxy.newProxyInstance(
		target.getClass().getClassLoader(), // 类加载器
		target.getClass().getInterfaces(),  // 目标类实现的接口数组
		new LogInvocationHandler(target)    // 拦截处理器
);
```

会在运行时动态生成一个代理对象，通常名为 `$Proxy0`。这个只出现在内存中，但是可以通过添加下述代码来记录这个动态生成的对象（JDK 8 及其之前版本）：

```java
System.getProperties().put("sun.misc.ProxyGenerator.saveGeneratedFiles", "true");
UserService proxy……
```

如果是 JDK 9 及其之后版本：

```java
System.getProperties().put("jdk.proxy.ProxyGenerator.saveGeneratedFiles", "true");
UserService proxy……
```

## 序列化与反序列化

序列化：将内存中的对象（数据结构）转换成可存储或传输的格式（字节流、JSON、XML、Protobuf 等）。

反序列化：序列化的逆过程。

在 Java 原生序列化中，Java 对象经过序列化之后会变成一串二进制字节流：

```java hl:17
import java.io.ObjectOutputStream;
import java.io.FileOutputStream;
import java.io.Serializable;

class User implements Serializable {
    String name = "";
    User(String name){
        System.out.println("构造方法调用");
        this.name = name;
    }
}

public class Demo{
    public static void main(String args[]) throws Exception{
        FileOutputStream fos = new FileOutputStream("name.ser");
        ObjectOutputStream os = new ObjectOutputStream(fos);
        os.writeObject(new User("Bob"));
        os.close();
    }
}
```

编译 → 运行，会得到一个 `name.ser` 文件，里面存储的就是 `User` 的实例对象序列化后的结果：

开头总是 `AC ED` 这个魔数头，后面的两字节 `00 05` 表示协议版本号。

反序列化：

```java hl:20
import java.io.*;

class User implements Serializable {
    String name = "";
    User(String name){
        System.out.println("构造方法被调用");
        this.name = name;
    }
}

public class Demo{
    public static void main(String args[]) throws Exception{
        FileOutputStream fos = new FileOutputStream("name.ser");
        ObjectOutputStream os = new ObjectOutputStream(fos);
        os.writeObject(new User("Bob"));
        os.close();

        FileInputStream fis = new FileInputStream("name.ser");
        ObjectInputStream ois = new ObjectInputStream(fis);
        User u = (User)ois.readObject();
        System.out.println(u.name);
    }
}
```

输出：

```
构造方法被调用
Bob
```

不难发现，“构造方法被调用”这句话是在：

```java
new User("Bob")
```

的时候调用了构造方法从而打印出来的。而反序列化，虽然是一个从二进制字节流转变成对象的过程（**类似**于创建了一个对象），但是其中并不涉及到该对象构造方法的调用，因此“构造方法被调用”这句话仅输出了一次。

>[!question] 为什么要这样设计呢？
> 构造方法往往会给一些属性赋值，而在序列化的时候，这些属性会被写入到二进制字节流中，反序列化的时候，JVM 会根据这些二进制字节流来恢复对象，本身就会参考二进制版的属性，如果再执行一遍构造方法，反而多此一举。

再来看一个例子：

```java
import java.io.*;

class Animal {
    Animal() { System.out.println("Animal 构造"); }
}

class Dog extends Animal implements Serializable {
    String name = "默认名";
    Dog(String name) { System.out.println("Dog 构造"); this.name = name; }
}

public class Demo {
    public static void main(String[] args) throws Exception {
        ByteArrayOutputStream bos = new ByteArrayOutputStream();
        new ObjectOutputStream(bos).writeObject(new Dog("旺财"));

        ObjectInputStream in = new ObjectInputStream(new ByteArrayInputStream(bos.toByteArray()));
        Dog d = (Dog) in.readObject();
        System.out.println(d.name);
    }
}
```

输出：

```
Animal 构造
Dog 构造
Animal 构造
旺财
```

反序列化恢复 Dog 对象的时候，虽然没有调用 Dog 的构造方法，但是调用了其父类的构造方法，因此出现了两次“Animal 构造”。

这其实有一个准确的规则的，即从子类开始往上找，找到**第一个没有实现 `Serializable` 接口的父类**，只执行它的无参构造方法（以及它往上的部分），这个类以下的构造逻辑全部跳过。

> [!attention]
>  如果找到的第一个没有实现 `Serializable` 接口的父类并没有无参构造方法，则会报错。

按上例走一遍，`Dog` 往上开始找，找到第一个没有实现 `Serializable` 接口的父类即 `Animal`，以此类为分界线：

- 此类的子类、孙类……的构造方法均不执行
- 此类、此类的父类、爷类的无参数构造方法均执行

## 其他值得注意的点

| 注意点                    | 描述                                                                                                  |
| ---------------------- | --------------------------------------------------------------------------------------------------- |
| `Serializable`         | 类本身实现或从父类继承了该接口才能序列化；所有非 `transient`、非 `static` 字段的值也必须可序列化，否则抛 `NotSerializableException`。         |
| 访问修饰符                  | 可序列化类中的字段不论 `public`/`protected`/`private`/`final`，都会被序列化和还原。JDK 通过反射发现字段，通过 `Unsafe` 读写字段值。        |
| `transient` 和 `static` | 默认机制不会序列化它们；`transient` 字段可在自定义 `writeObject`/`readObject` 中手动处理。                                   |
| 构造方法                   | [[#序列化与反序列化\|上一节]]已经详细讲过，这里不再赘述。                                                                    |
| 不可序列化的父类               | 其字段不进字节流，还原值由其无参构造方法和字段初始化决定。                                                                       |
| `readObject` 调用顺序      | 从最上层的可序列化类往下，每层若定义了签名完全匹配的 `private void readObject(ObjectInputStream)`，则在反序列化的时候就通过反射调用；每层只负责本层字段。 |
| `serialVersionUID`     | 反序列化时比较字节流与当前类的版本号，不一致抛 `InvalidClassException`；未声明时由 JVM 根据类结构计算，类一改就会变，建议手动声明。                    |
